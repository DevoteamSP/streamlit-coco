This guide describes streamlit-coco 0.1.9.

streamlit-coco is a Python/Streamlit library that embeds Snowflake's Cortex Code Agent SDK ("CoCo") into a Streamlit app: a right-rail or full-panel Copilot, human-in-the-loop approval gates for destructive tools, a live preview of an app CoCo just wrote, structured output into your own widgets, and a headless query() / CocoSession API for scripts and CI. Package status is alpha (Development Status :: 3 - Alpha).

This guide is for the people who run, maintain, and extend streamlit-coco itself — not for someone building a Streamlit app on top of it (that reader wants the User Guide).

Not covered#

  • Skills module — no .cortex/skills/*/SKILL.md at the repo root. App Builder's own types/*/SKILL.md files are in-example CoCo guideline skills, documented under extending instead of a reference-skills-style chapter.
  • Snowflake objects — the library creates or owns no Snowflake DDL. All SQL execution happens through the agent's own SQL tool, approval-gated, using whatever the connected role can do; there is no reference-procedures chapter.
  • Native App — no manifest.yml / snowflake.yml in this repo. Not shipped.
  • Deployment modes — only one target ships today: local (Streamlit, the CoCo CLI, and the Snowflake config on the same host). Streamlit in Snowflake (SiS) and SPCS are threat-model and roadmap scope only; they are not implemented, so install has one target, not a modes chapter.
  • Controls catalogue — no rule files or scoring rubric in this repo.
  • Infrastructure as code — no *.tf files in this repo.
